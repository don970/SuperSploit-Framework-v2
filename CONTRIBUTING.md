# Contributing to SuperSploit Framework (Core)

We welcome contributions to the open-source core of the SuperSploit Framework! Your help makes SuperSploit better for everyone.

Please note that contributions are currently accepted only for the **Core Framework** components, which are licensed under the MIT License. Proprietary Pro Tier features are not open for external contributions.

## How to Contribute

### 1. Reporting Bugs

If you find a bug, please open an issue on our GitHub repository. Before submitting, please:

*   **Check existing issues:** Your bug might already be reported.
*   **Provide clear steps to reproduce:** Describe how to trigger the bug.
*   **Include error messages:** Copy and paste any relevant error output.
*   **Specify your environment:** OS, Python version, SuperSploit version.

### 2. Suggesting Enhancements

Have an idea for a new feature or an improvement to an existing one in the Core Framework?

*   Open an issue on GitHub.
*   Clearly describe the enhancement and its potential benefits.
*   Explain why you think it would be a valuable addition.

### 3. Submitting Pull Requests (Code Contributions)

We appreciate code contributions! To ensure a smooth process, please follow these guidelines:

*   **Fork the repository:** Start by forking the `SuperSploit-Framework-v2` repository to your GitHub account.
*   **Create a new branch:** For each feature or bug fix, create a new branch from `main` (e.g., `feature/my-new-feature` or `bugfix/fix-issue-123`).
*   **Write clean, well-commented code:** Adhere to existing coding styles.
*   **Add tests:** If your contribution adds new functionality, please include appropriate tests.
*   **Update documentation:** If your changes affect how a feature works or add a new one, update the relevant documentation.
*   **Commit messages:** Write clear and concise commit messages.
*   **Open a Pull Request:**
    *   Target the `main` branch of the SuperSploit repository.
    *   Provide a clear description of your changes.
    *   Reference any related issues (e.g., `Fixes #123`).
