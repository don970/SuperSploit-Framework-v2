# SuperSploit Project Instructions

## Architecture: Pro-Tier Social Engineering & Delivery Suite (Deep Analysis)

The SE Suite represents SuperSploit's initial access and payload delivery layer. These tools are engineered to manipulate human trust and local network environments to bypass traditional perimeter security, facilitating the deployment of payloads generated by the framework.

---

### 1. Web Stager & AitM Proxy (`web_stager_gui.py`)
*Objective: Clone target web portals, intercept live credentials, and bypass Multi-Factor Authentication (MFA) via session hijacking.*

| Mechanism | Description |
| :--- | :--- |
| **Reverse Proxy Engine** | Uses `requests` to dynamically fetch and serve the upstream target (e.g., `login.microsoftonline.com`) to the victim. It rewrites HTTP headers (stripping encoding) to ensure transparent delivery. |
| **Credential & Cookie Harvesting** | Intercepts POST requests, extracting variables matching `user`, `pass`, `email`, and `login`. Captures `Set-Cookie` headers from the upstream server to steal authenticated session tokens. |
| **Dynamic DOM Injection** | Parses the incoming HTML and uses regex to inject malicious JavaScript (e.g., BeEF hooks, keyloggers) right before the closing `</body>` tag. |
| **Payload Integration** | Includes a dedicated `/download` endpoint that securely serves active SuperSploit payloads directly from the framework's workspace. |

### 2. Active DNS Patcher (`dns_patcher_gui.py` / Embedded in Web Stager)
*Objective: Force local network clients to resolve legitimate domains (e.g., `google.com`) to the attacker's AitM Proxy.*

| Mechanism | Description |
| :--- | :--- |
| **Packet Interception** | Uses Scapy's `sniff` on UDP Port 53 (with `promisc=False` to prevent Wi-Fi driver crashes) to intercept outbound DNS queries (`DNSQR`). |
| **IPv4 Packet Forgery** | Crafts malicious `DNSRR` (Resource Record) responses. Crucially, it mirrors the `id`, `qd`, and `rd` (Recursion Desired) flags to prevent modern OS stub resolvers from dropping the forged packet. |
| **Dynamic Loopback Routing** | Inspects the source IP of the query. If the query originates locally (`127.0.0.1` or the host's IP), it allows Scapy to route internally. This prevents the physical Access Point from detecting MAC/IP spoofing and disconnecting the attacker. |

### 3. Evil Twin AP & Captive Portal (`evil_twin_gui.py` & `se_captive_portal.py`)
*Objective: Coerce target devices into connecting to a rogue wireless network to capture WPA handshakes or serve captive portal phishing pages.*

| Mechanism | Description |
| :--- | :--- |
| **Daemon Orchestration** | Dynamically writes configuration files for `hostapd` (Access Point) and `dnsmasq` (DHCP/DNS) and spawns them as root subprocesses. |
| **DNS Sinkholing** | Configures `dnsmasq` with `address=/#/192.168.99.1`, forcing all HTTP traffic to resolve to the attacker's local HTTP server, creating a Captive Portal trap. |
| **Deauth Engine** | Integrates with `aireplay-ng` (`-0` flag) in a background thread to forcefully disconnect clients from the legitimate BSSID, forcing them to auto-connect to the Rogue AP. |

### 4. Advanced SMTP Spoofing Suite (`smtp_gui.py` & `se_smtp_spoofer.py`)
*Objective: Execute high-fidelity phishing campaigns capable of bypassing basic spam filters using spoofed sender identities.*

| Mechanism | Description |
| :--- | :--- |
| **Multi-Part MIME Assembly** | Constructs robust `MIMEMultipart` emails, allowing for the embedding of rich HTML templates and binary attachments (e.g., trojanized PDFs or APKs). |
| **Header Manipulation** | Injects custom `From`, `Reply-To`, and `X-Mailer` (e.g., `Microsoft Outlook 16.0`) headers to spoof organizational identities and evade simplistic anti-spam heuristics. |
| **Batch Dispatching** | Parses CSV files for target lists and dynamically injects target-specific variables into the HTML template prior to SMTP transmission. |

### 5. SMS Smishing & VoIP Engine (`sms_gui.py` & `se_sms_sender.py`)
*Objective: Deliver payloads directly to mobile targets via SMS, bypassing email-based security controls.*

| Mechanism | Description |
| :--- | :--- |
| **Tri-Modal Delivery** | Supports three distinct delivery vectors: **HTTP API** (e.g., Twilio), **Direct SIP UDP** (raw packet injection to port 5060), and **Free Carrier Relays** (SMTP to SMS gateways like `@vtext.com`). |
| **Raw SIP Injection** | Crafts custom `MESSAGE sip:... SIP/2.0` UDP packets, dynamically generating branch tags and Call-IDs to spoof SMS messages via open VoIP trunks. |

### 6. iMessage / RCS Native Injector (`imessage_gui.py` & `se_imessage_injector.py`)
*Objective: Achieve native delivery of SE payloads via Apple's proprietary iMessage infrastructure.*

| Mechanism | Description |
| :--- | :--- |
| **OSAScript Bridging** | Leverages the macOS `osascript` binary to interact directly with the local `Messages` daemon. This bypasses the need for API keys and ensures the message is delivered as a trusted "Blue Bubble" from the host's Apple ID. |

### 7. Malicious QR Generator (`qr_gui.py` & `se_qr_generator.py`)
*Objective: Bridge the physical and digital attack surface via "Asset Drops."*

| Mechanism | Description |
| :--- | :--- |
| **High-Error Correction** | Forces the `ERROR_CORRECT_H` constant, ensuring the QR code remains scannable even if printed and partially damaged/obscured in the physical environment. |

## Automation & Integration Workflow

These tools are designed to be chained together into complex delivery pipelines:

1. **The Physical Drop**: The **QR Generator** creates a malicious asset pointing to the attacker's public IP.
2. **The Phish**: The **SMTP/SMS/iMessage** modules blast the target with urgent lures, driving them to the link.
3. **The Trap**: The target connects. If they are local, the **Evil Twin** or **DNS Patcher** forces their traffic to the attacker.
4. **The Harvest**: The **AitM Proxy** intercepts the connection, steals the target's session cookies and credentials, and silently drops the **Native APK Payload**.
